---
name: tmux
description: |
  Команды, которые повиснут, захватят терминал или ждут человека, — в
  панели tmux, не в bash:
  - долгая команда (сборка, тесты, скачивание, сервер, ожидаемо больше
    30 секунд): bash блокирует ход, панель — нет; о завершении сессии
    приходит сообщение, опрос и sleep запрещены;
  - команда, ожидающая человеческого ввода (sudo, pacman, интерактивные
    промпты);
  - показать пользователю документ (`edit path/to/file:123`): редактор в
    bash захватывает терминал диалога, в панели — рядом с диалогом.
---

## Когда использовать

- Команда ожидаемо дольше 30 секунд (сборка, тесты, скачивание, сервер,
  бенчмарк): bash блокирует ход, панель — нет, о завершении приходит
  сообщение.
- Команда может ждать человеческого ввода (sudo, pacman, интерактивные
  промпты): в bash это тупик до таймаута, в панели вводит человек.
- Нужно показать пользователю документ (`edit path/to/file:123`): в
  bash редактор захватывает терминал диалога, в панели открывается
  рядом.

## Порядок работы

```text
tmux.py -- {command}
```

Выводит `pane_id`, можно использовать для мониторинга.

Команда исполняется в шелле пользователя (`$SHELL`, tmux ставит его по
default-shell). Окружение агента (`PI_*`) в панель не попадает — нужное
передавай команде явно.

После запуска — закончи ход или займись независимой работой.

Чтобы проверить всё ли в порядке в с запущенной задачей:

```text
tmux.py dump-screen -p {pane_id}
```
## Справка по tmux.py

```text
Usage: tmux.py [<subcommand>] [flags] [--] <command...>

По умолчанию (без подкоманды): выполняет команду в панели текущего окна.

Подкоманды:
  status                  Окна и карта панелей сессии
  dump-screen -p <id>     Вывести содержимое панели (любое окно сессии)

Флаги:
  -d, --cwd <dir>   рабочая директория
  -p, --pane <id>   ID панели (dump-screen)

Флаги заканчиваются на команде: после первого слова команды все
аргументы принадлежат команде. Полный список и точная семантика:
tmux.py -h.
```
